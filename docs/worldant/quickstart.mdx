---
title: Quickstart
description: Create, build, serve, and call a minimal Worldant world.
---

Create a world:

```bash
worldant init todo
cd todo
```

`init` downloads the latest public template and creates a single-app world:

```text
todo/
  worldant.ts
  migrations/
  commands/
  workflows/
    steps/
  lib/
  tests/
```

The generated `worldant.ts` has separate world and wire node identities plus explicit bind address,
port, WebTransport, and WebSocket settings. The normalized defaults are equal, but they serve
different purposes: `name` identifies callable addresses and `wire.nodeName` identifies this node.

Add a migration under `migrations/0001_init.sql`:

```sql
create table todo_items (
  id bigint generated always as identity primary key,
  title text not null,
  done boolean not null default false,
  created_at timestamptz not null default now()
);
```

Add a Command under `commands/add.ts`:

```ts
import { pgpaw } from "worldant"

export default async function add(input: { title: string }) {
  const reply = await pgpaw.sql(
    "insert into todo_items (title) values ($1) returning id, title, done, created_at",
    [input.title],
  )
  return reply.rows[0]
}
```

Build and serve:

```bash
worldant build
worldant serve
```

Serve requires the complete generated `wire` object. It publishes a snapshot, loads configuration
from that snapshot, and binds every enabled transport before reporting readiness.

Call it:

```ts
import { createWorld } from "worldant-client"

const world = createWorld({ url: "ws://127.0.0.1:8787/__worldant/v1/ws" })
const todo = await world.todo.add({ title: "Buy milk" }, { key: "todo:add:buy-milk" })
```

Use Workflows for work that must survive retries, waits, process failure, or restart.
